# Roteiro para o vídeo demonstrativo (aprox. 4 minutos)

**Atenção:** este arquivo é o roteiro. O vídeo MP4 precisa ser gravado pelo estudante, mostrando o site em execução e narrando a demonstração. Grave a tela com a ferramenta do sistema, OBS Studio ou outro gravador disponível.

## Preparação

1. Abra `index.html` no navegador ou inicie `python -m http.server 8000` e abra `http://localhost:8000`.
2. Deixe a janela do navegador maximizada.
3. Ative a gravação de tela e, se possível, grave também sua narração.
4. Demonstre os recursos sem acelerar demais a navegação.

## Roteiro sugerido — 4 minutos

### 0:00–0:30 | Apresentação

“Este é o Acesso para Todos, um site desenvolvido para a atividade de Programação Web sobre acessibilidade. O objetivo é apresentar a importância da inclusão no cotidiano e demonstrar práticas para desenvolver páginas acessíveis. O projeto foi construído com HTML, CSS e JavaScript.”

### 0:30–1:10 | Navegação e estrutura

Mostre o menu e abra as páginas **No cotidiano**, **Barreiras** e **Tecnologia assistiva**.

“ O site possui seis páginas interligadas. O menu aparece em todas elas, os links descrevem seu destino e cada página tem título principal, seções organizadas e conteúdo em linguagem direta.”

Mostre o link “Pular para o conteúdo principal”, pressionando Tab até ele aparecer e depois Enter.

### 1:10–2:00 | Recursos de acessibilidade

Mostre os botões **A+**, **A−** e **Alto contraste**. Aumente o texto, ative o contraste e depois restaure a aparência normal.

“Também foram incluídos controles para aumentar e diminuir o texto, ativar alto contraste e ouvir o conteúdo por meio da síntese de voz do navegador. Nenhum áudio começa automaticamente.”

### 2:00–2:50 | Conteúdo educativo

Abra **Como criar uma web acessível** e mostre os tópicos de HTML semântico, navegação por teclado, imagens, contraste e multimídia.

“O conteúdo aborda alternativas textuais para imagens, links descritivos, hierarquia de títulos, navegação por teclado, contraste, linguagem clara, legendas e transcrições.”

### 2:50–3:30 | Checklist interativo

Abra **Boas práticas e avaliação**, marque alguns itens do checklist e clique em **Ver resultado da revisão**. Mostre a mensagem atualizada.

“Esta página oferece uma lista de verificação inicial. Ela não substitui testes manuais nem certifica conformidade, mas ajuda a organizar a avaliação.”

### 3:30–4:00 | Encerramento e fontes

Mostre a parte final das referências.

“O projeto utiliza como base os materiais eMAG Conteudista, módulos 1 e 2, fornecidos para a atividade. Também consulta as páginas oficiais do eMAG e a WCAG 2.2 do W3C como referência complementar. A proposta é mostrar que acessibilidade é uma prática contínua, pensada para ampliar a participação de todas as pessoas.”

## Conferência antes de enviar

- [ ] Duração entre 3 e 5 minutos.
- [ ] Site aparece em funcionamento, não apenas o código-fonte.
- [ ] Todas as seis páginas são mostradas ou citadas.
- [ ] Os controles de acessibilidade são demonstrados.
- [ ] O checklist interativo é utilizado.
- [ ] Áudio/narração está audível, ou o vídeo possui legendas.
- [ ] O MP4 está dentro da pasta do projeto antes de compactar para enviar ao AVA.
